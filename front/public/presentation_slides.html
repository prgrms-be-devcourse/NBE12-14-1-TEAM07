주문 상태 관리 방식 개선 (State Machine)

4. 프로젝트 수행 경과
초기 상태 모델 (한계)
ORDERED ➔ COMPLETED

수량 수정 여부, 상세 품목 취소, 전체 취소 구분이 불가능하여 관리자/사용자 간 변경 이력 추적 실패.

최종 2단계 상태 머신 구조
Orders.status
ORDERED MODIFYED CANCELED
OrdersDetail.status
ORDERED MODIFYED DETAIL_CANCELED CANCELED

🔄 핵심 비즈니스 상태 전이 규칙 (Transition Rules)

1. 주문 수량/품목 수정 시:

주문 엔티티 상태를 수정 상태로 전이

Orders ➔ MODIFYED
2. 특정 품목 상세 취소 시:

취소된 품목 상태 변경 및 주문 엔티티 동기화

Detail ➔ DETAIL_CANCELED
Orders ➔ MODIFYED
3. 주문 전체 취소 시:

기존 DETAIL_CANCELED 품목을 제외한 잔여 품목 전이

잔여 Detail ➔ CANCELED
4. 14:00 관리자 일괄 처리 시:

취소되지 않은 정상/수정 주문 일괄 완료

전체 ➔ COMPLETED
✨ 회의를 거쳐 단순 CANCELED 처리 대신 주문과 주문상세의 상태를 분리해 변경 이력을 완벽히 보존하도록 구체화.

❌ 단순 CANCELED 처리: 추후 주문 전체 취소 시, '부분 취소된 품목'과 '마지막에 취소된 품목'을 구분 불가.
